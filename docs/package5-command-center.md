# بسته پنجم — مرکز دریافت، پیگیری و تنظیمات هوشمند

مبنا: نسخه ۴۵، Commit `90d6819bffe6f2c6cb8e41c385309b86331ba14a`.
شاخه: `feature/package5-command-center`.

## قابلیت‌های قابل استفاده

- صفحه `/manage/connections` در سربرگ و پوسته مشترک موجود: تعریف و ویرایش منابع، فعال/غیرفعال‌کردن، آزمون فقط‌خواندنی، سلامت، خطا، آخرین دریافت و روش ارسال. تنظیمات فقط برای Owner مجاز است؛ حساب یا نقش جدیدی ایجاد نشده است.
- چهار Gmail و منبع تماس فعلی به‌عنوان تنظیم اولیه غیرفعال نمایش داده می‌شوند؛ نشانی به معنی مجوز OAuth نیست. تعداد منبع سقف قراردادی جدید ندارد، اما ظرفیت Worker، DB، API و پیمایش محدود است.
- OAuth گوگل با PKCE، state یک‌بارمصرف ده‌دقیقه‌ای، تطبیق نشانی صندوق، scope فقط‌خواندنی و refresh token رمزگذاری‌شده. پاسخ Google API، آزمون مجوز و ورود اطلاعات از یکدیگر جدا هستند. ورود Gmail در صفحه‌های ۲۵تایی، حفظ cursor پس از خطا و آزمون دسترسی، تکرار امن رویداد و ثبت خطای پاک‌سازی‌شده انجام می‌شود.
- رابط امضاشده برای فرم سایت، پیام‌رسان، تلفن، درگاه مشتری و عامل استاندارد ایمیل وجود دارد. همه به `dispatchCreate`، همان پرونده، سمت سازمانی، وظیفه و اعلان موجود متصل‌اند؛ هیچ موتور جدیدی ایجاد نشده است.
- رویداد مستقل ایمیل صرف شباهت متن یکی نمی‌شود؛ ادامه مکالمه با `replyToEventId` همان منبع ممکن است. تماس یکسان شیت و ثبت مستقیم در همان روز از کنترل تکرار موجود استفاده می‌کند. رویداد هم‌شناسه با متن یا هویت/مرجع تغییرکرده رد می‌شود.
- شماره فاکتور فقط همراه با تطبیق دقیق تماس مشتری به سند موجود متصل می‌شود؛ ارتباط مالی از `writeFinance/link_operation` با کنترل سازگاری پرونده ساخته می‌شود. رسید ارسالی هیچ پرداختی را تأیید نمی‌کند؛ تطبیق بانک و اختیار مالی موجود حفظ شده است.
- عنوان کارکنان «مدیریت و پیگیری درخواست‌ها» است. دسته‌بندی فنی و اصلاح قواعد در نمای کارکنان پنهان شده‌اند؛ وظیفه، سمت، وضعیت و موعد با همان کارتابل ادامه می‌یابند.
- فهرست خدمات مجری داخلی/خارجی روی شناسه همان خدمات مصوب نگهداری می‌شود: قیمت خرید ریالی، زمان اجرا و وضعیت خدمت؛ مستقل از قیمت فروش مشتری. این فهرست به‌تنهایی قیمت یا سفارش را تصویب نمی‌کند.
- تنظیم OpenAI یا حالت غیرفعال، نام مدل، کلید رمزگذاری‌شده و حدود مصرف مصوب مالک به دستیار فعلی اضافه شده‌اند؛ سهمیه پیش‌فرض تازه‌ای تحمیل نشده است. محدودیت هزینه بر رزرو محافظه‌کارانه تنظیم‌شده مالک مبتنی است و جای صورتحساب واقعی ارائه‌دهنده را نمی‌گیرد.
- منابع دانش متنی و فایل‌های TXT/Markdown/PDF/Word، نسخه‌بندی، تأیید، خروج از دسترس، دسته و کنترل مجوز دارند. PDF/Word نیازمند متن استخراج‌شده و بررسی‌شده‌اند؛ استخراج خودکار ادعا نشده است. بازیابی محدود به نسخه جاری مصوب و مجاز و حداکثر چهار گزیده است؛ اجازه ارسال گزیده به مدل خارجی جداگانه لازم است.

## آزمون و وضعیت واقعی

`node scripts/test-finance-runtime.mjs package5-command-center-runtime.mjs --package5-fixtures`

۱۲۶ بررسی HTTP موفق روی Worker واقعی کامپایل‌شده با D1/R2 موقت و هویت‌های ساختگی. سناریوها: OAuth و Gmail ساختگی تا کارتابل؛ تکرار تماس شیت/ثبت مستقیم؛ اعلام واریزی، اتصال فاکتور، بانک و تأیید مالی؛ یک سفارش پیوسته از تعرفه و پیش‌فاکتور تا سفارش کار، نمونه، QC، تأیید مستقل، تحویل و بازگشت نمونه؛ تیکت رفع اشکال و پاسخ مصوب؛ قطع/بازیابی اتصال، امضا و کنترل مجوز؛ منابع دانش، نسخه و بارگذاری؛ نمایش HTML تنظیمات و صفحه کارکنان. TypeScript و Build موفق‌اند. مجموعه آزمون بسته‌های قبلی مجدداً اجرا نشده است.

پاسخ‌های Google در `tests/package5-provider-fixtures.mjs` صریحاً ساختگی و فقط با flag آزمون‌اند؛ به کد Worker تولیدی وارد نمی‌شوند. هیچ ادعای اتصال OAuth واقعی، ورود اطلاعات بانک واقعی، ارسال ایمیل واقعی یا جابه‌جایی فیزیکی نمونه نمی‌شود. اطلاعات واقعی برای آزمون تغییر نکرده‌اند. Migration لازم نیست.

Secret جدید رمزگذاری `SYNAPSE_INTEGRATION_KEY` در مسیر رسمی میزبانی، بدون نمایش مقدار، ثبت شده است؛ هیچ API پولی، OAuth واقعی، زمان‌بند یا ارسال بیرونی فعال نشده است. سایر Secrets حفظ شده‌اند. شماره انتشار و Commit نهایی فقط پس از پاسخ موفق میزبان در گزارش تحویل و مرجع آخرین نسخه ثبت می‌شوند.

## موارد هنوز غیرفعال یا نیازمند اقدام

1. چهار اتصال Gmail موجود در ChatGPT، مجوز مستقل Google Cloud سامانه نیستند. `GOOGLE_OAUTH_CLIENT_ID` و `GOOGLE_OAUTH_CLIENT_SECRET`، ثبت callback و رضایت هر صندوق/شیت لازم است. هیچ حسابی مخفیانه به‌جای حساب دیگر استفاده نمی‌شود.
2. شیت تماس مرجع فعلی بدون تغییر محفوظ است. برای ورود مستقیم Google Sheets، منبع باید یک Sheet بومی و دارای ستون‌های استاندارد زیر باشد؛ فایل XLSX نیازمند عامل تبدیل مجاز یا تبدیل تأییدشده مالک است.
3. واتساپ، بله، روبیکا، تلگرام، اینستاگرام، لینکدین، تلفن و پورتال مشتری API اختصاصی فعال ندارند. وب‌هوک مشترک آماده اتصال است؛ لینک دستی و ثبت مدرک در مکاتبات موجود معادل اتصال خودکار نیست.
4. IMAP/SMTP در Worker فعلی اجرا نمی‌شود؛ عامل استاندارد مجاز خارج از Worker باید با پورت امضاشده ارتباط برقرار کند. ارسال بیرونی این نسخه دستی و مستند است؛ Gmail OAuth فقط‌خواندنی است و scope ارسال درخواست نمی‌کند.
5. زمان‌بند قبلی میزبان خاموش باقی مانده است. اجرای مستقل تا ثبت Secret زمان‌بند و تنظیم cron معتبر انجام نمی‌شود. اجرای خودکار با ChatGPT Work جایگزین اجرای مستقل معرفی نشده است.
6. مدل واقعی به API Key، مدل معتبر، اعتبار جداگانه و حدود مصوب نیاز دارد. تنها adapter عملیاتی این نسخه OpenAI است؛ قرارداد `AssistantProvider` برای توسعه ارائه‌دهندگان دیگر حفظ شده است.
7. بانک تعرفه مصوب فعلی مشترک و معتبر باقی است. همگام‌سازی خودکار قیمت‌ها از Google Sheets تعرفه هنوز فعال نشده و منبع جدید بدون تأیید مالی نرخ را تغییر نمی‌دهد.

بنابراین معیار «دریافت خودکار تمام منابع واقعی بدون حضور مدیریت» هنوز محقق نشده است؛ علت، نبود مجوز مستقل منابع و زمان‌بند است، نه موفقیت یا شکست آزمون‌های ساختگی. فعال‌سازی باید از تنظیمات مالک و مسیر رسمی Secrets انجام شود، بدون فرستادن کلید در چت یا GitHub.
