# SYNAPSE — سیاست دائمی ثبت تغییرات، نسخه‌بندی و بازیابی

**وضعیت:** دستور اجرایی پیشنهادی برای Work، Codex و ChatGPT؛ اجرای واقعی هر مرحله نیازمند ابزار و مجوز فعال است.
**مخزن اصلی خصوصی:** `30napse-design/synapse-ai-management`
**مرجع نسخه منتشرشده هنگام تنظیم سیاست:** `main = 8f13eb3dd5ff3db4df54b3c4666771750faca273`

## اصول قطعی
1. GitHub مرجع واحد تاریخچه کد است؛ Google Drive آرشیو مستقل نسخه‌های تحویلی و مستندات؛ ChatGPT Sites محیط انتشار فعلی.
2. پیش از هر تغییر، آخرین `main`، شاخه فعال، Commit مبنا و نسخه زنده بررسی و ثبت شوند. اگر تفاوتی وجود دارد، **بدون حدس یا بازنویسی** گزارش شود.
3. هر کار در شاخه مستقل `feature/<short-task>-<date>` یا `fix/<short-task>-<date>` انجام شود؛ از ویرایش مستقیم `main` و Force Push به آن خودداری شود.
4. به‌روزرسانی دیتابیس، R2، Secrets، سطح دسترسی، انتشار و اعمال Migration فقط با درخواست و تأیید صریح جداگانه انجام شود. توسعه ظاهری باید تغییرات اجرایی را دست‌نخورده بگذارد.
5. قبل از Commit، بررسی نشت رمزها، `.env`، توکن‌ها و اطلاعات مشتریان انجام شود؛ هیچ داده عملیاتی، D1/R2، یا Secret در GitHub یا گزارش گفتگو قرار نگیرد.
6. هر تغییر باید Build/Tests قابل اجرا، فهرست فایل‌ها، Commit واقعی و لینک شاخه/PR داشته باشد. نتیجه «موفق» فقط پس از دریافت پاسخ موفق ابزار و خواندن دوباره Commit اعلام شود.
7. پس از تأیید کاربر، تغییرات از طریق PR به شاخه مرجع ادغام شود؛ **پس از انتشار واقعی**، نسخه زنده و SHA منتشرشده مستقل ثبت شوند. تغییر GitHub به معنی انتشار خودکار Sites نیست.
8. برای نسخه‌های تحویلی مهم، نسخه قابل بازیابی (ZIP سورس یا Git bundle)، CHANGELOG، Manifest شامل SHA و SHA-256، نتیجه آزمون بازیابی و دستور نصب در Google Drive خصوصی ذخیره و **وجود و صحت فایل‌ها تأیید شود**.
9. پوشه‌بندی Drive: `۰۱ — نسخه‌های کامل و قابل بازیابی`؛ `۰۲ — تغییرات Codex`؛ `۰۳ — تغییرات و انتشارهای Work`؛ `۰۴ — پایگاه داده و راهنمای پشتیبان‌گیری`؛ `۰۵ — راهنمای نصب و انتقال هاست`. خروجی‌های Codex و Work زیر مسیر مربوطه و با نام تاریخ+شاخه+SHA نگهداری شوند. در صورت ایجاد نسخه مرجع تأییدشده، پوشه ۰۱ هم به‌روز شود.
10. `SYNAPSE-LATEST.json` فقط با مقادیر واقعی و پس از راستی‌آزمایی به‌روزرسانی شود: آخرین نسخه تحویلی، آخرین نسخه تأییدشده و آخرین نسخه منتشرشده **سه وضعیت جداگانه‌اند**.
11. اگر هر محیطی به GitHub/Drive دسترسی ندارد یا انتقال شکست خورد، **موفقیت ادعا نشود**؛ کار متوقف یا فقط به‌عنوان `pending-sync` گزارش شود و بسته patch/bundle/manifest برای انتقال دستی امن آماده شود. هیچ همگام‌سازی فرضی انجام نشود.
12. از اجرای مکرر، ZIPهای تکراری یا آپلود بی‌دلیل پس از هر Commit کوچک خودداری شود: هر Commit در GitHub ثبت شود؛ Drive برای تحویل پایان هر کار/نسخه مهم و قبل از انتشار، و برای تغییرات حساس قبل و بعد از عملیات استفاده شود.
13. R2 و D1 فقط پس از دریافت خروجی رسمی و امکان تست بازیابی، در فضای خصوصی رمزگذاری‌شده و جدا از مخزن کد نگهداری شوند. `STAFF_AUTH_PEPPER` تنها با مسیر امن تأییدشده منتقل شود، نه در تیکت، Drive بدون رمزگذاری یا ChatGPT.
14. هیچ یک از Work، Codex یا ChatGPT نباید ادعای توانایی اجرای خودکار در سایر محیط‌ها بدون تأیید دسترسی و اجرای واقعی داشته باشد. این سند به تنهایی Trigger یا اتصال خودکار ایجاد نمی‌کند.

## چک‌لیست تحویل هر کار
- شرح تغییر و محدوده؛ وضعیت پیش/پس؛ مرجع Commit
- شاخه و Commit لینک‌دار؛ فهرست تغییرات؛ Build و Tests
- وضعیت PR / تأیید / ادغام / انتشار زنده (هرکدام جدا)
- لینک فایل آرشیو Drive، نام و SHA-256، و تأیید بازخوانی آن (برای نسخه‌های مهم)
- هر مرحله ناموفق به همراه علت و اقدام بعدی
- تأیید اینکه D1، R2، رمزها و انتشار زنده بدون مجوز تغییر نکرده‌اند

**هدف:** قابلیت بازسازی مستقل SYNAPSE بدون سردرگمی در انتخاب نسخه، و بدون خطر برای سامانه زنده.
