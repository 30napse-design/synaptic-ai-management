# موجودی لازم برای انتقال مستقل SYNAPSE — ادامه بسته پنجم

این سند فهرست پیش‌نیاز است، نه ادعای تحویل بکاپ یا شروع مهاجرت. روش‌های قبلی در `docs/independent-runtime-fa.md` و `docs/package5-independent-connectors.md` حفظ می‌شوند.

| جزء | محل/قرارداد فعلی | اقدام لازم در مقصد |
| --- | --- | --- |
| سورس و Build | GitHub خصوصی؛ Vinext/Worker، lockfile و اسکریپت‌ها | دریافت SHA دقیق منتشرشده، نصب نسخه‌های قفل‌شده و Build |
| داده عملیاتی | D1، binding `DB`؛ schema و Migrationهای موجود در `drizzle/` | خروجی کامل سازگار، حفظ شناسه‌ها/روابط/نسخه‌ها؛ تعیین SQLite یا PostgreSQL و adapter سازگار پیش از انتقال |
| حساب و نشست | staff_accounts، staff_sessions، staff_members، انتصاب سمت‌ها و history | حفظ IDها؛ انتقال امن pepper یا برنامه بازنشانی مصوب؛ هیچ اعتماد به header دلخواه کاربر در مقصد |
| فایل خصوصی | R2، binding `BUCKET`؛ work/science/laboratory/finance/knowledge object keys در DB | خروجی کامل bytes، object_key، MIME و metadata؛ مقصد S3-compatible یا ذخیره خصوصی با همان کنترل مجوز |
| دریافت و گردش | ops_items، ops_communications، research_orders/people، workflow links، tasks و notifications | همان موتور و شناسه‌ها؛ callbackها و URL پایه با دامنه مقصد؛ کنترل تکرار مشترک حفظ شود |
| تنظیمات منابع | staff_auth_settings: input-source/input-health/input-oauth | حفظ cursor و تاریخ شروع؛ OAuth state موقت لازم نیست به‌عنوان اتصال فعال منتقل شود |
| زمان‌بند فعلی | task ابری ساعتی ChatGPT، شناسه در گزارش تحویل | وابستگی به ChatGPT؛ در مقصد با cron خصوصی و `/api/integrations/tick` جایگزین و واقعاً آزمون شود |
| Secrets احراز هویت | `STAFF_AUTH_PEPPER`، تنظیم provisioning موجود | مقدار فقط از مسیر رسمی امن؛ نه Git/گزارش عمومی. provisioning منقضی در مقصد فعال نشود |
| Secret رمزگذاری تنظیمات | `SYNAPSE_INTEGRATION_KEY` | حفظ امن همان کلید برای رمزگشایی OAuth/API keys؛ در صورت نبود خروجی رسمی، بازاتصال مصوب به‌جای ادعای بازیابی |
| OAuth گوگل | `GOOGLE_OAUTH_CLIENT_ID`/`GOOGLE_OAUTH_CLIENT_SECRET`؛ فعلاً فراهم نیست | Web client، consent و scopeهای فقط‌خواندنی Gmail/Sheets؛ ثبت callback دامنه جدید، رضایت حساب‌های دقیق |
| cron مستقل | `SYNAPSE_AUTOMATION_TOKEN`؛ فعلاً تنظیم نشده | Secret مستقل و header مجاز؛ اجرای دوره‌ای، logs و هشدار شکست/باقی‌ماندن backlog |
| اتصالات بومی ChatGPT | چهار Gmail، Drive و MCP مالک | قابل انتقال به‌صورت token از این ابزار نیستند؛ OAuth یا سرویس استاندارد مستقل جایگزین شود |
| پیام‌رسان/IMAP/SMTP/تلفن | پورت مشترک امضاشده آماده؛ provider مستقل فعال نیست | انتخاب سرویس قانونی، کلید و امضای مستقل، idempotency و receipt واقعی؛ ارسال مجاز انسانی حفظ شود |
| AI اختیاری | adapter فعلی و نام‌های `OPENAI_API_KEY` و `SYNAPSE_AI_*` در env نمونه | برای شروع مهاجرت ضروری نیست؛ بدون خرید/فعال‌سازی جدید. تنظیمات دانش/قیمت محرمانه‌اند |
| دامنه، TLS و داده‌برداری | مبدأ chatgpt.site؛ هیچ انتقالی انجام نشده | تعیین VPS/Node/container سازگار، دامنه و TLS، انتقال آزمایشی و کنترل کامل پیش از تغییر DNS |

Hostinger shared/PHP hosting به‌تنهایی Worker دارای `cloudflare:workers` و bindingهای D1/R2 را اجرا نمی‌کند. باید runtime مقصد و adapterهای داده/فایل/هویت انتخاب شوند؛ سورس آماده بازیابی است، اما انتقال عملیاتی هنوز آماده یک‌کلیک نیست. فایل ZIP سورس جای خروجی DB و فایل خصوصی را نمی‌گیرد. هیچ Secret واقعی یا داده مشتری در این فهرست وجود ندارد.

## اصلاح TLS شاخه hostinger-nextjs-fix — ۲۲ نوامبر ۲۰۲۶

مبنای این اصلاح `c2a0b3b` است. در این شاخه، `scripts/start-hostinger.mjs` پیش از اجرای Next.js به PostgreSQL متصل می‌شود؛ خطای TLS در همین اتصال مانع شروع وب‌سرور و موجب 503 می‌شود. تنظیم قبلی `sslmode=verify-full` اعتبارسنجی را فعال می‌کرد، اما CA خصوصی Supabase را به مجموعه اعتماد Node اضافه نمی‌کرد. همچنین پارامترهای SSL داخل connection string در کتابخانه `pg` می‌توانند کل شیء `ssl` برنامه را جایگزین کنند.

- `runtime/postgres-tls.mjs` تنظیم مشترک اتصال شروع برنامه و Pool عملیاتی را آماده می‌کند. بررسی زنجیره گواهی و نام میزبان فعال می‌ماند و حداقل TLS نسخه ۱.۲ است. گزینه‌های تضعیف اعتبارسنجی برای اتصال راه دور پذیرفته نمی‌شوند.
- گواهی عمومی **Supabase Root 2021 CA** از نشانی HTTPS رسمی زیر در سورس قرار گرفته است؛ این گواهی Secret یا کلید خصوصی نیست. اعتماد پیش‌فرض Node حفظ می‌شود و این CA فقط برای میزبان‌های `*.supabase.co` و `*.pooler.supabase.com` اضافه می‌شود. نام‌های مشابه خارج از این دامنه‌ها این اعتماد را دریافت نمی‌کنند.
- منبع: `https://supabase-downloads.s3.amazonaws.com/prod/ssl/prod-ca-2021.crt`
- SHA-256: `807025ad50d4ed219d2c9c7d299c004f824eb00cf7f65afef607d07b72e6cafa`؛ اعتبار گواهی تا ۲۶ آوریل ۲۰۳۱ است. چرخش CA باید با گواهی معتبر جدید انجام شود، نه با خاموش‌کردن اعتبارسنجی.
- اگر پروژه CA متفاوتی دارد، مسیر موجود `sslrootcert` در URL، متغیر استاندارد `PGSSLROOTCERT` یا PEM در `SYNAPSE_POSTGRES_CA_CERT` پشتیبانی می‌شود. PEM چندخطی یا دارای `\n` پذیرفته می‌شود. تنظیم صریح مالک بر گواهی پیش‌فرض اولویت دارد و فایل ناخوانا/گواهی نامعتبر خطای روشن می‌دهد. هیچ‌یک از تنظیمات Hostinger در این مأموریت تغییر نکرده‌اند.
- پارامترهای SSL پس از خواندن تنظیمات از URL برداشته و به‌صورت گزینه‌های صریح به `pg` داده می‌شوند تا CA و کنترل اعتبارسنجی بازنویسی نشوند. گواهی/کلید کلاینت و مذاکره مستقیم TLS، در صورت تعیین قبلی، حفظ می‌شوند. اطلاعات اتصال در پیام خطای URL نامعتبر درج نمی‌شود.

راستی‌آزمایی: `node tests/postgres-tls.test.mjs` تنظیم نهایی پس از پردازش `pg`، اتصال مستقیم/pooler، CA رسمی و رد تنظیمات ناامن را کنترل می‌کند. آزمون محلی با CA و کلیدهای موقت، یک `SELECT 1` را از طریق پروتکل PostgreSQL روی TLS اجرا می‌کند و رد CA ناشناس و نام میزبان اشتباه را نیز اثبات می‌کند. این یک سرویس ساختگی محلی است؛ اتصال واقعی Hostinger/Supabase در دسترس نبوده و موفقیت آن ادعا نمی‌شود. هیچ Migration یا Query روی دیتابیس واقعی اجرا نشده است. صفحات، APIها، حساب‌ها و منطق گردش کار تغییر نکرده‌اند.

مرجع الزامات Supabase: `https://supabase.com/docs/guides/database/connecting-to-postgres` و `https://supabase.com/docs/guides/platform/ssl-enforcement`؛ توصیه رسمی، اعتبارسنجی کامل CA و نام میزبان است. هیچ تغییری به `main` یا سایت اصلی منتقل نمی‌شود؛ بررسی رفع 503 واقعی نیازمند استقرار همین Commit در Hostinger توسط مسیر مجاز مالک است.

## به‌روزرسانی Final31 — ۱۹ نوامبر ۲۰۲۶

- ادامه آزمایشگاه‌ها روی شاخه `feature/laboratory-final31-2026-11-19` از نسخه زنده ۵۸ آماده می‌شود؛ تغییر سورس مساوی انتشار نیست. دستور و شواهد در بخش Final31 سند `laboratory-mother-completion.md` ثبت شده‌اند.
- کتابخانه‌های PDF/Excel و فونت مجاز مالی، قفل نسخه‌ها و Migrationهای 0022/0023 همراه سورس مالی نگهداری می‌شوند. Migrationها فقط در محیط ساختگی بررسی شده‌اند و روی D1 زنده اجرا نشده‌اند. ترتیب مقصد باید همان ترتیب فایل‌های drizzle باشد؛ پیش از اجرا روی داده واقعی، سازگاری/نسخه پشتیبان/بازیابی باید اثبات شوند.
- DB باید خروجی کامل و سازگار شامل schema، rows، قیود و migration state داشته باشد؛ BUCKET باید همه object keyها، bytes، metadata و manifest با checksum را پوشش دهد. تطبیق ارجاعات DB به objectها و بازیابی روی محیط مستقل قبل از DNS cutover ضروری است. ابزارهای فعلی چنین خروجی/بازیابی واقعی را تحویل نداده‌اند.
- نام Secretها و bindingها در `.env.example` و راهنمای اجرای مستقل موجودند؛ این تغییر Secret تازه‌ای نمی‌خواهد. مقدار STAFF_AUTH_PEPPER و کلید رمزگذاری اتصال‌ها باید فقط از مسیر رسمی امن منتقل شود؛ در Git یا گزارش Drive قرار نمی‌گیرد.
- راه بازگشت کد، نسخه ۵۸ و Commit `559e2a899d3dfdc62b30f1e342c84b9af38584c0` است. بازگشت کد به‌تنهایی بازگردانی DB/R2 نیست. طبق بند ۳۰ دستور جدید، انتشار تا احراز پشتیبان معتبر و دروازه‌های آزمون متوقف است.
